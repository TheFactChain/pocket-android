# Сборка Pocket Android

Эта инструкция предназначена для разработчиков. Скрипты запускаются на Windows
и собирают APK для Android 10 и новее (ARM64 и ARMv7). Для установки готового
приложения используй [последний выпуск](https://github.com/TheFactChain/pocket-android/releases/latest).

## Требования

- Windows x64, PowerShell 7 и Git.
- Android SDK: Android SDK Platform 35, Build Tools 36.0.0, Platform Tools и
  NDK 28.2.13676358. Установи их через SDK Manager в Android Studio или используй
  уже подготовленный SDK.
- Интернет для загрузки инструментов, исходников движков и зависимостей Gradle/Go.
- Один свободный диск с буквой R–Z: скрипты временно назначают его папке проекта
  через `subst`, чтобы Android AIDL и нативные инструменты получали ASCII-путь.
  После сборки назначение снимается, исходники не перемещаются.

Версии и SHA-256 архивов Java 17 и Go закреплены в
[tools/toolchain.lock.json](../tools/toolchain.lock.json). Gradle Wrapper использует
Gradle 8.7, Android Gradle Plugin — 8.6.1. Устанавливать системную Java или Go
для этого сценария не требуется.

## Подготовка

В PowerShell 7 клонируй репозиторий и получи подмодуль SetupWizardLibrary:

```powershell
git clone https://github.com/TheFactChain/pocket-android.git
Set-Location pocket-android
git submodule update --init --recursive
.\tools\Setup.ps1 -AndroidSdk 'C:\Android\Sdk'
```

`C:\Android\Sdk` — пример: подставь фактический путь к своему SDK. Все следующие
команды запускаются из корня репозитория.

`Setup.ps1` загружает Java и Go из официальных источников, проверяет SHA-256
архивов, готовит `gomobile`/`gobind` и создаёт постоянную локальную подпись.
Повторный запуск использует уже подготовленные инструменты и ключ. Путь к SDK
записывается в локальный `local.properties`; SDK и системные настройки Java/PATH
скрипт не меняет. Переменные среды настраиваются только для текущего процесса.

## Нативные движки

Текущий Java-код использует sing-box libbox и обёртку Xray. Для чистой сборки
нужен AAR, содержащий оба движка:

```powershell
.\tools\Build-Libbox.ps1 -VerifySourceOnly
.\tools\xray\Build-Cores.ps1
Copy-Item -LiteralPath '.tools\pocket-cores\out\pocket-cores.aar' -Destination 'app\libs\libbox.aar'
```

Первая команда получает sing-box v1.14.4, проверяет закреплённый commit и SHA-256
патча Pocket, применяет только этот патч и сверяет итоговый diff. Второй скрипт
собирает общий AAR для `arm64-v8a` и `armeabi-v7a` с Xray-core v1.260327.0;
он запрашивает Go toolchain 1.26.11. Последняя команда устанавливает общий AAR
в путь, который использует [app/build.gradle](../app/build.gradle).

**Ограничение автоматизации:** `tools/xray/Build-Cores.ps1` пока помечен как
черновой и не включён в `Build.ps1`. Если `app/libs/libbox.aar` отсутствует,
`Build.ps1` вызывает обычный `Build-Libbox.ps1`, который собирает только libbox
и не предоставляет требуемые Java-классы Xray. Поэтому подготовку общего AAR
выше нельзя пропускать. Обычный `Build-Libbox.ps1` без `-VerifySourceOnly`
перезаписывает этот AAR вариантом без Xray.

Архивы Java/Go и исходный commit/патч sing-box проверяются по закреплённым
значениям. Это не гарантия побайтовой воспроизводимости всего выпуска:
комбинированный скрипт отдельно получает Go toolchain и зависимости Xray.

## Сборка и проверки

```powershell
.\tools\Build.ps1
```

Скрипт выполняет unit-тесты приложения и lint release, собирает release/debug
Pocket, APK инструментальных тестов и отдельное тестовое приложение Pocket Probe.
Инструментальные тесты при этом **собираются, но не запускаются на устройстве**.

Затем проверяются подпись release APK, идентификатор приложения
`io.github.nekontritce11123.pocketandroid`, название Pocket, минимум API 29,
запрет отладки, необходимые и исключённые компоненты итогового манифеста,
архитектура и ELF/ZIP-выравнивание нативных библиотек. Build Tools 36.0.0 выбран
также из-за исправления неэкранированных Windows-путей в генерируемом AIDL-коде.

Основной результат: `app/build/outputs/apk/release/app-release.apk`.
Отчёт нативной проверки: `.artifacts/native-apk-check.json`.

По умолчанию `versionCode` и `versionName` берутся из
[app/build.gradle](../app/build.gradle). Для выпуска меняй значения там;
разовое переопределение кода проверочной сборки доступно параметром:

```powershell
.\tools\Build.ps1 -VersionCode 24
```

Самостоятельная сборка подписана твоим локальным ключом. Она не обновит APK
официального выпуска с другой подписью. Проверяй её на отдельном тестовом
устройстве: не удаляй рабочий профиль или данные ради замены подписи.

## Сохрани подпись

Ключ `.local/signing/pocket.p12` и его параметры находятся в `.local/signing/`.
Доступ к каталогу ограничивается текущим пользователем Windows и SYSTEM.
Сохрани **весь каталог** в защищённой резервной копии: потеря ключа не позволит
обновлять уже установленные сборки с этой подписью. Ключ и пароли нельзя
передавать вместе с исходниками или APK.

`.tools/`, `.local/`, `.artifacts/`, `local.properties`, APK и AAR исключены из Git.
Не включай настоящие подключения, ключи и пароли в исходники, тестовые данные,
журналы или публикуемый APK. Происхождение и лицензии компонентов описаны в
[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

## Проверка приложения

Успешная сборка и проверка APK не подтверждают работу VPN, отсутствие утечек
или сохранение данных после обновления. Установка, запуск, обновление поверх
существующего профиля и проверка маршрута выполняются отдельно по
[инструкции аппаратных проверок](device-checks.md). Сохраняй существующий профиль
и его данные; для чистого создания профиля используй свободное тестовое устройство.

Сборка не публикует выпуск. Публикация APK выполняется отдельно после приёмки.
