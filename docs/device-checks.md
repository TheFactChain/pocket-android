# Аппаратная проверка Pocket

Это инструкция, не отчёт о пройденных проверках. Статусы и блокеры хранятся в
Beads, свидетельства — в локальном .artifacts/ без настоящих ключей. Запись проверки
содержит этап, версию/SHA-256 APK, устройство/прошивку, протокол, условия сети,
ожидание, наблюдение и ссылку на свидетельство. Результат: «пройдено»,
«не пройдено» или «не проверено».

## Устройство и обновление

Подключи выбранный POCO по USB, включи отладку и подтверди компьютер. Оставь
экран разблокированным для системных запросов установки. Проверяй связь через
adb devices -l, прошивку/ABI через getprop и владельца через dpm list-owners.
Не удаляй существующий профиль, не снимай администратора, не очищай данные
и не выполняй factory reset. Чистое provisioning проверяется отдельно на свободном
тестовом устройстве/эмуляторе. HyperOS может запрещать shell доступ к user 11:
политику читай через API Pocket, маршрут проверяй отдельным UID.

Выполни tools/Build.ps1. Сохрани SHA-256 release APK и отчёт
.artifacts/native-apk-check.json; подпись должна совпадать с предыдущей.
Установка: adb -s <serial> install --user 0 -r <apk>, без uninstall.
После обновления проверь owner, профиль, сохранённый сервер и повторный запуск.
Успешная установка сама по себе не подтверждает сохранение данных.

## Инструментальные тесты и секреты

Установи debug APK той же подписи и app-debug-androidTest.apk. Запуск:
adb -s <serial> shell am instrument --user 0 -w io.github.nekontritce11123.pocketandroid.test/androidx.test.runner.AndroidJUnitRunner

Тесты используют синтетические значения: упаковка, Keystore/AES, сохранение
выбора без fallback после удаления, конфигурации реального libbox и отсутствие
plaintext snapshot при старте CommandServer без TUN. Они не подтверждают маршрут
обычного приложения. Перед передачей установи release актуального versionCode
и проверь работу после R8 и запрет отладки.

Настоящие подключения не включаются в общую APK, исходники, задачи и журналы.
Разрешённая локальная передача для debug-установки:
tools/Install-TestProfile.ps1 -Serial <serial> -ProfilePath <private-local-json>

Передача идёт stdin в приватные данные личной копии, после открытия Pocket —
через проверенный Binder в зашифрованное рабочее хранилище. После подтверждения
сохранения/выбора временный файл удаляется. Проверь факт удаления, не выводя
содержимое. Release той же подписи сохраняет Keystore и профиль.

## Маршрут, приложения и отказы

Установи probe-debug.apk в личный профиль, скопируй обычным интерфейсом Pocket.
Подтверди системные запросы для тестового приложения. Запуск из рабочего списка
и ярлыка должен показывать отдельный UID/UserHandle. Личный запуск сохраняет
свой UID и обычный маршрут. Проверь HTTPS-выход, системный DNS и UDP на совместимой
контролируемой цели, затем обычный и split APK, раздельные данные, запуск/ярлык
и удаление только рабочей копии.

Локальная цель TCP/UDP: tools/Observe-Network.ps1 -ListenAddress <pc-lan-ip>
-Port 55887 -Seconds 90 -EvidencePath <local-jsonl>.
Используй уникальные пути /pocket-test/<run-id> и помеченные UDP-запросы.
Перед отказом докажи доступность наблюдателя контрольным запросом. Рабочий UID
не должен приходить к локальной цели напрямую. Выход через шлюз сверяй с адресом
и журналом контролируемой внешней цели. Значок VPN и статус UI не заменяют наблюдение.

При недоступном сервере и гибели только :vpn наблюдай непрерывные помеченные
запросы минимум 60 секунд; отдельно IPv4, IPv6 при наличии, DNS/Private DNS/DoH
и LAN. Неподдерживаемый трафик должен завершаться ошибкой без прямого выхода.
Не останавливай и не перенастраивай личный VPN.

Повтори после закрытия Pocket, перезагрузки/разблокировки, смены сети, режима
полёта и паузы профиля. Зафиксируй время восстановления и один движок. При отказе
выбранного B сервер A не должен возвращаться автоматически. Удаление активного
сервера оставляет сеть заблокированной.

Проверь отмены системных запросов, поворот/пересоздание во время установки,
крупный шрифт и клавиатуру. Прерванная установка должна завершать сессию
и позволять повтор. Ярлык удалённого приложения/профиля не открывает личную копию.
Обязательная непроверенная часть блокирует приёмку этапа. Результаты относятся
к указанному SHA-256 APK; после изменений повторяют затронутые сценарии.
